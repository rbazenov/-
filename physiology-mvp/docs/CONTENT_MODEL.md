# Модель контента MVP

## Минимальные поля карточки

- `card_id`
- `topic_id`
- `learning_objective_id`
- `title`
- `body_ru`
- `source_refs`: массив ссылок на источники и конкретные локаторы
- `source_locator`: глава, раздел, страница или URL основного источника
- `asset_refs`: идентификаторы иллюстраций с отдельными лицензиями и атрибуцией
- `license`: например CC BY 4.0
- `adaptation_type`: translation / summary / paraphrase / original
- `change_note`: что изменено относительно источника
- `review_status`: draft / reviewed / approved / rejected
- `reviewer`
- `version`

## Минимальные поля вопроса

- `question_id`
- `learning_objective_id`
- `prompt_ru`
- `options`: массив вариантов
- `correct_option_id`
- `explanation_correct_ru`
- `explanation_wrong_ru`: по вариантам или по типичным ошибкам
- `difficulty`: baseline / application / transfer
- `assessment_role`: practice / delayed_check
- `misconception_tags`
- `source_id`
- `license`
- `adaptation_type`
- `review_status`
- `version`

## Файлы пилотного банка

- `content/pilot/muscle/cards.json` — 16 теоретических карточек.
- `content/pilot/muscle/questions.json` — 48 тренировочных вопросов (`assessment_role: practice`).
- `content/pilot/muscle/delayed_checks.json` — 12 отложенных проверочных вопросов (`assessment_role: delayed_check`). Они не должны показываться вместе с тренировочными вопросами до отдельного режима проверки.
- `content/pilot/tourism/` — стартовый модуль туризма: 4 карточки, 12 тренировочных вопросов, 4 отложенные проверки; все элементы `draft`.
- `content/pilot/topography/` — стартовый модуль топографии: 4 карточки, 12 тренировочных вопросов, 4 отложенные проверки; все элементы `draft`.

Предметы описаны в `apps/web/src/content.ts`. У каждого предмета независимые `cards`, `questions`, `delayedQuestions`, `baseOrder` и статус. Прогресс хранится по `subjectId`; активный предмет находится на верхнем уровне сессии, неактивные — в `saved`.

## Правила генерации

1. Генерировать только из разрешённых и проверенных фрагментов.
2. Сохранять смысл механизма; не добавлять новые факты без источника.
3. Для каждой учебной цели иметь несколько сопоставимых вариантов вопроса.
4. Перемешивать варианты ответа.
5. Не показывать правильный ответ после первой ошибки, если выбран такой режим, но после повторной попытки дать объяснение.
6. Отдельно хранить контрольные вопросы, которые студент не видел при обучении.
7. Не использовать баллы как точный процент готовности к экзамену.
8. Русский текст писать по `docs/TEXT_STYLE.md`: без служебных префиксов «Верно:», рекламных усилителей и канцелярских вставок. Оценка ответа показывается интерфейсом, объяснение содержит только суть.

## Атрибуция

Для каждой публичной карточки должна быть доступна информация:
- автор и название источника;
- ссылка;
- лицензия;
- отметка о переводе/адаптации;
- отсутствие подразумеваемого одобрения со стороны автора источника.

Для материалов Douglas College дополнительно сохраняем требуемую книгой фразу и ссылку, например:
“Download for free at https://pressbooks.bccampus.ca/dcbiol11031109”

Полные шаблоны и чек-лист: `docs/ATTRIBUTION.md`. Атрибуция должна быть доступна пользователю на экране карточки или в явно связанных сведениях о ней; одного скрытого поля в базе недостаточно.
